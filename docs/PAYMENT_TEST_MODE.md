# Payment simulation

The owner requested test mode because no Midtrans merchant account is active. Checkout is a local simulator, not a Midtrans sandbox connection. QRIS, DANA, GoPay, OVO and bank are test choices only. The QR demo opens a signed, 30-minute browser payment page, not a QRIS/EMV wallet payload. The phone page shows only a test reference, amount and status. A CSRF-protected POST completes the simulation; GET never pays. Wallet references begin with DEMO and are not account numbers. There is no provider request, real charge, COD option, or proof of settlement. A successful test records simulated_paid separately from reservation and food order status. Admin approval and stock checks remain required.

PAYMENT_DEMO_ENABLED defaults to true for this requested demo. Set it to false to disable new simulations. Activate and verify a merchant account before implementing real checkout, signed notifications, reconciliation and server-side provider status checks. Never treat test_payments as real receipts.

The expiry alert requires the rental page to stay open. The customer explicitly enables audio and optional notifications. Alarm volume follows the device, repeats every five seconds until acknowledged, stopped by the session ending/extension, disabled, or the page is closed, and can be stopped. Browser or operating system background restrictions can delay or suppress audio. No closed-app alarm is promised.
